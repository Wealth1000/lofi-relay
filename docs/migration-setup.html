lofi-relay migration — owner setup guide

Companion to issue #3 · branch master · no card needed anywhere · no secrets stored in this document
What changed, in one breath

Live testing on 2026-10-13 proved that YouTube's live ladder carries audio-only HLS renditions (itag 234/233) whose segments are pure AAC — no video track, ~130 kb/s. So the entire "relay downloads video, strips it, ships AAC" job disappears: no one anywhere downloads video bytes.

What remains — resolving the signed m3u8 URLs — moves off Render's flagged static IP onto GitHub Actions (free, no card, rotating runner IPs, uncapped minutes on this public repo). It publishes a small JSON to this repo; your .lofi client plays the signed m3u8 straight from YouTube's CDN. The Cloudflare Worker is an optional hardening hop, not a requirement.

1 Add the two repo secrets

The workflow needs the existing cookie-jar pair — the same values your Render deployment already uses. No new Gist, no new token: the JSON is published to this repo via the workflow's built-in token.

SecretWhat it isWhere you already have it
JAR_GIST_ID The cookie-jar Gist's ID (32-hex, from its URL github.com/gists/abcdefgh…) Render → lofi-relay → Environment, or the playwright-gist-updater repo
JAR_GITHUB_TOKEN Read-only gist-scoped PAT that can read the jar Same places, same variable

CLI (fastest, values pasted from your password manager / Render env):

gh secret set JAR_GIST_ID      -R Wealth1000/lofi-relay --body "PASTE_GIST_ID"
gh secret set JAR_GITHUB_TOKEN -R Wealth1000/lofi-relay --body "PASTE_TOKEN"

…or the UI: repo → Settings → Secrets and variables → Actions → New repository secret. Secrets are never printed into logs; the workflow reads them into the runner's memory only.

2 Trigger the first resolver run

Once the implementation from issue #3 lands (it adds the workflow), either wait for the 30-minute cron or force it now:

  • repo → Actions → the resolver workflow → Run workflow → master

Watch for:

3 The gate: prove playback from your IP

Stop here until this passes

Everything so far resolved the URLs from a runner IP. Your player runs on your residential IP. The one untested assumption in the whole design is whether YouTube's signature is IP-bound. This test settles it in under a minute — run it on your desktop, after Step 2:

URL=$(curl -fsS \
  https://raw.githubusercontent.com/Wealth1000/lofi-relay/master/data/streams.json \
  | jq -r '.streams["relax-study"].url')

# 1. shape check — expect an audio stream, NO video stream, ~100–200 kb/s
ffprobe -hide_banner "$URL"

# 2. listen check — 30 seconds of music
timeout 30 mpv --no-video "$URL"
Pass ffprobe lists an aac stream and no video stream, and mpv plays. Render teardown is authorized (Step 6). No Worker needed.
Fail (403 / "Request denied") Signatures are IP-bound. Two pre-planned escapes, in order:
  1. Enable the Cloudflare Worker hop (Step 5) — Cloudflare's network fetches the segments; your IP never touches YouTube's CDN directly.
  2. Local-resolve fallback — .lofi (rewritten) already degrades to mpv + local yt-dlp, the ytcava path. Your residential IP is exactly the one YouTube likes. Works today, no infrastructure.

4 Swap your .lofi

The agent commits a rewritten .lofi. On your machine:

  1. Pull the repo (or copy the file), point your shell config at the new .lofi, then source your .zshrc.
  2. Verify: lofi -h lists the streams (names now canonical, config-derived), lofi -r plays with cava + media widget + artwork.
  3. Confirm the pinger is gone: pgrep -f 'sleep 600' returns nothing during playback. Nothing has to stay awake anymore.

5 Optional: the Cloudflare Worker hop

Only if Step 3 failed and you want the proxy route (or you simply like the ~900 KB DVR playlist trimmed to a live-edge window). All of it card-free:

  1. Account: sign up at dash.cloudflare.com — email only, no card. Create a free Workers zone subdomain (lofi-relay.<you>.workers.dev).
  2. CLI: npm i -g wrangler then wrangler login (browser OAuth — no API token needed).
  3. Deploy: the agent commits the Worker. Run wrangler deploy in the worker's directory.
  4. Key: bind the existing API key so the worker keeps its quota shield: wrangler secret put LOFI_API_KEY (paste the key your Render service uses).
  5. Verify: 
    curl -fsS -H "X-API-Key: $LOFI_API_KEY" \
  "https://lofi-relay.<you>.workers.dev/health"
# then ffprobe a /lofi/relax-study URL through the worker

Quota reality: one 24/7 listener ≈ 22 k requests/day (segments ≈5 s) vs the free 100 k/day cap. You use a quarter of it with one stream; concurrent listeners scale linearly.

6 Cutover & Render teardown (gated follow-up)

The spec gates this on 7 days of clean runs on the new path: no stale status for more than one cron cycle, no gate failures, no local-resolve fallbacks needed.

  1. Delete the Render service (keep the image/repo app/ as fallback source).
  2. Strip LOFI_API_KEY from .lofi and any client config (the direct path has no auth; Worker path reuses the key if you kept it).
  3. README gets the new architecture section (agent task in the issue).
  4. History cleanup of the long-hardcoded key (BFG / filter-repo) is a separate task — the key stops being live at step 2, but it remains readable in old commits until a rewrite.
